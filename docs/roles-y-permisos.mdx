# Roles y permisos

Cada persona que usa Oblicua RFID (en la app móvil o en la plataforma web) tiene asignado uno de **4 roles**. El rol determina qué pantallas puede ver y qué acciones puede ejecutar, tanto en el móvil como en la web.

| Rol | Para quién |
|---|---|
| **Administrador** | Configuración, usuarios, cierre de inventario y todo lo demás. |
| **Supervisor** | Opera y resuelve: concilia, valida, ajusta, cierra. No gestiona usuarios ni la sincronización. |
| **Operador** | Ejecuta conteos en el móvil y consulta el estado operativo en la web. No resuelve diferencias ni cierra. |
| **Auditor** | Solo lectura, en todo (incluida auditoría y usuarios). No modifica nada. |

Un usuario nuevo entra siempre como **Operador** (el mínimo privilegio); un administrador lo asciende desde [Usuarios](/docs/plataforma-web/usuarios).

## En la plataforma web

| Pantalla / acción | Admin | Supervisor | Operador | Auditor |
|---|:---:|:---:|:---:|:---:|
| Dashboard, Conteos, Detalle, Conciliación, Historial (ver) | ✅ | ✅ | ✅ | ✅ |
| Validación documental (ver) | ✅ | ✅ | — | ✅ |
| Diferencias (ver) | ✅ | ✅ | ✅ | ✅ |
| Diferencias — justificar / traslado / ajuste | ✅ | ✅ | — | — |
| Traslados (ver / registrar) | ✅ | ✅ | — | solo ver |
| Ajustes de inventario (ver / registrar) | ✅ | ✅ | — | solo ver |
| Cierre de inventario (ver / ejecutar) | ✅ | ✅ | — | solo ver |
| [Sincronización](/docs/plataforma-web/sincronizacion) (ver / gestionar) | ✅ | solo ver | — | solo ver |
| Auditoría (ver) | ✅ | ✅ | — | ✅ |
| Usuarios (ver / gestionar) | ✅ | — | — | solo ver |

El menú lateral solo muestra las secciones a las que cada rol tiene acceso; si alguien entra a una URL sin permiso, la plataforma lo redirige. En las pantallas de acción (validar, ajustar, cerrar, etc.), los botones se ocultan o quedan deshabilitados para quien no puede ejecutarlos.

## En la app móvil

| Capacidad | Admin | Supervisor | Operador | Auditor |
|---|:---:|:---:|:---:|:---:|
| Dashboard, Historial, Diferencias (ver) | ✅ | ✅ | ✅ | ✅ |
| Iniciar y sincronizar conteos | ✅ | ✅ | ✅ | — |

Un auditor que entra a la app ve el botón **"Nuevo Conteo"** deshabilitado, con la nota "Tu rol no permite iniciar conteos".

## Segunda línea de defensa

Estos mismos permisos se aplican también dentro de la base de datos: aunque alguien intentara forzar una acción sin pasar por la interfaz, el servidor la rechaza igual. Por eso los permisos no dependen únicamente de lo que muestra la pantalla.

:::note
El alta de usuarios desde [Usuarios](/docs/plataforma-web/usuarios) crea el registro visible, pero asignar o cambiar el rol de una cuenta todavía es una operación que hace un administrador directamente sobre la base de datos.
:::

## Recuperación de contraseña

Cualquier usuario, sin importar su rol, puede recuperar su contraseña si la olvida.

- **Plataforma web**: en [Inicio de sesión](/docs/plataforma-web/inicio-de-sesion), enlace **"Recuperar contraseña"** → se pide el correo → llega un enlace para definir una nueva.
- **App móvil**: en [Inicio de sesión](/docs/app-movil/inicio-de-sesion), enlace **"¿Olvidaste tu contraseña?"** → se escribe el correo en el campo Usuario → el enlace de recuperación se abre en la plataforma web para definir la nueva contraseña.
